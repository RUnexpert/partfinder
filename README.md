# Partfinder

Клиентское приложение на React + Redux Toolkit, JavaScript без TypeScript. Bootstrap 5 и собственные адаптивные стили. Пользователь вводит артикул, выбирает производителя и получает исходную деталь, вложенные аналоги и складские предложения.

## Быстрый старт

Нужен Node.js 22+ и npm.

```sh
npm ci
cp .env.example .env
npm run dev
```

Открыть http://127.0.0.1:5173. Приложение запускается в явно обозначенном деморежиме. Для примеров используйте **01089** или **7160500039S**; другие артикулы в деморежиме возвращают пустой результат.

## Реальный API

В `.env` задайте ключ покупателя:

```dotenv
FAVORIT_API_KEY=ваш-ключ
FAVORIT_API_URL=http://api.favorit-parts.ru/hs/hsprice/
```

Перезапустите локальный сервер. В правом верхнем углу нажмите «Деморежим» и выберите «Favorit Parts API». Ключ берётся только из окружения сервера, не включается в клиентский код и не хранится в браузере. Не добавляйте префикс `VITE_` к имени секрета.

Для Netlify задайте `FAVORIT_API_KEY` в настройках сайта **Environment variables** (доступ для Functions), затем выполните повторный деплой и переключите режим в интерфейсе. Ключ не нужен на этапе сборки React.

Адрес HTTP взят из предоставленной документации от 06.03.2023. Прокси выполняет запросы к поставщику с сервера и устраняет ограничения CORS и mixed content в браузере. Поддержку HTTPS у поставщика следует подтвердить перед использованием реального ключа: если она есть, укажите HTTPS в `FAVORIT_API_URL`. HTTP передаёт ключ между сервером и поставщиком без шифрования.

Без действительного ключа реальные цены, доступность сервиса, его текущий контракт и квоты не проверены. Демоданные не являются предложениями поставщика. Формат RUB в интерфейсе — предположение для российского каталога: PDF не определяет валюту, её следует подтвердить у поставщика.

## Схема запросов

Браузер отправляет `POST /api/search` с JSON `{ "number": "01089" }`. Прокси добавляет ключ и выполняет GET к фиксированному адресу сервиса:

```text
?key=…&number=01089
```

При выборе производителя браузер передаёт `{ "number": "01089", "brand": "CAFFARO" }`. Прокси выполняет:

```text
?key=…&number=01089&brand=CAFFARO&analogues=on
```

Параметры кодируются через `URLSearchParams`. Артикул сохраняется как строка, включая ведущие нули; удаляются только пробелы в начале и конце. Нормализация дефисов используется только для демонстрационных примеров.

Из ответа `goods` выделяются уникальные бренды. На втором этапе `goods[].analogues` обходятся рекурсивно. Каждая запись `warehouses` становится отдельной строкой с `warehouses.price` и `warehouses.stock`. Устаревшее поле `goods.price` не используется. Если складов нет, цена отображается как «—», остаток берётся из `count`, строка помечена «Нет предложений». Неизвестные значения не превращаются в ноль. Повторяющиеся предложения одного товара на одном складе объединяются по идентификаторам.

Запросы после ввода задерживаются на 450 мс. При изменении артикула, бренда или режима предыдущий запрос отменяется; reducer проверяет requestId, чтобы запоздалый ответ не подменял текущий. Таймаут внешнего сервиса — 15 секунд. Есть состояния загрузки, пустые ответы `[{}]`, ошибки ключа, квот, HTTP, JSON и сети, а также повтор запроса.

## Структура

```text
src/main.jsx             интерфейс и взаимодействие
src/styles.css           адаптивные стили
src/store.js             Redux, async thunks, состояния запросов
src/api.js               запросы браузера
src/catalog.js           обработка товаров, брендов и предложений
src/demo.js              отдельные демонстрационные данные
worker/api.js            общий серверный обработчик API
scripts/dev.mjs          Vite + локальный API-прокси
scripts/build-worker.mjs сборка клиента в Worker ESM
```

`GET /api/config` сообщает только о наличии серверного ключа. Прокси не принимает произвольный URL от браузера, не открывает CORS и не возвращает тексты сетевых исключений с потенциальными секретами. Версия Netlify доступна по адресу сайта. До включения реального ключа на публичном сайте добавьте ограничения доступа или частоты запросов согласно квотам поставщика.

## Проверка и сборка

```sh
npm test
npm run build
npm run validate
```

Тесты проверяют договор API, складские цены, вложенные аналоги, отсутствие товара, дедупликацию, кодирование параметров, валидацию входа и сбои сервиса. Сборка создаёт автономный `dist/server/index.js`: Worker отдаёт React-интерфейс и обслуживает `/api/*`. Для обычного Node-сервера используйте локальный сервер либо подключите `handleAPI` к вашему серверу и отдавайте Vite-клиент статически.

Google Fonts используется для шрифта Golos Text. При недоступности сети интерфейс работает с локальным Arial.

Документация зависимостей: [Redux Toolkit](https://redux.js.org/toolkit/api/createAsyncThunk), [Vite](https://vite.dev/guide/).


## Деплой в Netlify

Репозиторий содержит `netlify.toml`: команда `npm run build:netlify`, каталог `dist`, Node.js 22. Функция `netlify/functions/api.mjs` обслуживает `/api/*` и использует тот же обработчик, что и локальный сервер. Внешний ключ остаётся только в серверном окружении.

Для нового сайта в Netlify выберите GitHub-репозиторий проекта: настройки сборки подхватятся автоматически. Для ручного деплоя через Netlify CLI:

```sh
npx netlify-cli deploy --prod --build
```

Без ключа сайт работает в деморежиме. Оригинальная команда `npm run build` по-прежнему собирает отдельный Worker-артефакт; для Netlify используйте `npm run build:netlify`.
